# Sniper-System platform — architecture

## Runtime shape of the Sniper-System platform

`app/main.py` builds the FastAPI app, mounts every router, and starts a background sweeper loop. The sweeper (`app/services/sweeper.run_sweep`) runs every 60 seconds in a worker thread (`asyncio.to_thread`); with `uvicorn --workers 4` (Dockerfile, since v4.82) a non-blocking `flock` on `/tmp/brotherbot-sweeper.lock` elects exactly one sweeping worker, the others serve requests only. The sweep drives the lane collector, the outcome resolver, the management journal, candle pruning, the event-reaction recorder, the market brief writer, the engineering watchers (v5.00) and warming of the cached evidence read model (v5.12). Startup also runs idempotent repairs: `news_map.backfill_mappings` (v2.4.1) and `webhooks.repair_signal_statuses` (v4.18).

Configuration is `app/config.py` (`pydantic-settings`, env prefix `BB_`, `.env` file). Notable keys (names only): `BB_SECRET_KEY`, `BB_OLD_SECRET_KEYS`, `BB_DATABASE_URL`, `BB_BASE_URL`, `BB_ENV`, `BB_BRAIN_WEBHOOK_SECRET`, `BB_EMAIL_PROVIDER` (console/smtp/brevo), `BB_SMS_PROVIDER`, `BB_METRICS_TOKEN`, `BB_AI_API_KEY`, `BB_AI_MODEL`, `BB_AI_WEEKLY_BUDGET_USD` (10.0), `BB_BRIDGE_URL`, `BB_BRIDGE_KEY`, `BB_CANDLE_1M_RETENTION_DAYS` (90), `BB_SENTRY_DSN`. Production runs Docker Compose: app + Postgres 16 + Redis (idle) + Caddy; `./backups` is mounted read-only into the app so the candle-wipe gate can see the pg_dump.

## Data flow, end to end

1. TradingView Pine fires an alert → `brain.signalmesh.dev/webhook/v18` (v18 brain); nginx mirrors a copy to v7. Neither is in this repo.
2. The v18 brain's mirror POSTs each decision to the platform: `POST /webhooks/brain/signal` (header `X-Brain-Secret`). The platform stores the verbatim payload in `Signal.raw_payload`, normalizes `system`, `tf`, symbol and timestamps, and appends `SignalEvent` timeline rows.
3. v7 POSTs its decision stream (accepts, rejects, blocks, gates, scores) to `POST /webhooks/brain/decision` (`DecisionEvent`), fire-and-forget from `bot.py` (docs/INTEGRATION_V7.md), and its artifacts/heartbeat to `/webhooks/brain/artifact` (`kind: "v7_heartbeat"`, v4.15).
4. The brain also pushes market bias (`/webhooks/brain/bias`, with `as_of`, spread fields), the economic calendar (`/webhooks/brain/news`), outlooks (`/webhooks/brain/outlook`), scenarios, incident updates (`/webhooks/brain/incident`, may not approve/resolve), and the bridge config (`/webhooks/brain/bridge-config`, v4.23).
5. The Windows MT5 reporter (`agents/mt5_reporter/mt5_reporter.py`, v1.7.0) POSTs with a per-user API key: `/api/v1/heartbeat/account`, `/api/v1/heartbeat/vps` (now carrying `service_version`, `git_commit`, `file_sha256`), `/api/v1/heartbeat/trade` (fills/closes), `/api/v1/heartbeat/candles` (closed bars only, from MT5 position 1), `/api/v1/heartbeat/feed-depth` (depth probes). `/webhooks/brain/candles` is the equivalent brain-side door; both share `upsert_candles`.
6. The sweeper turns stored candles into lane observations (`collector.record_all`), resolves outcomes with the frozen rules, writes market snapshots and briefs, and runs the watchers.
7. Pages render read models over these tables. Nothing flows back out to a bot, an executor or MT5.

## The signal mirror payload contract

The append-only field list (CLAUDE.md Iron Rule 2): `system`, `signal`, `direction`, `signal_id`, `symbol`, `tf`, `entry`, `sl`, `tp`, `tp1`, `tp2`, `rr`, `grade`. Appended over time by Pine and the mirror, all read from the verbatim payload: `pine_ver` (since v18.8; the only version key — v4.91), `payload_schema` (2), `trades_today` (v18.11), `struct`, `entry_dist_atr` (v18.12), `htf_full`, `v6_spread` (a 3-bar range-stress proxy, never renamed), `pine_signal_id` (the canonical join key), `pine_system` (v4.12), `fired_at`, `session`, `score` (forwarded since PLAT-MIRROR-1 / v5.00), `fail_soft`, `fail_soft_reason`, `fail_soft_count`, optional `fail_soft_max` (v5.18), `council {approve,total}`, `status`, `confidence`, `backfill`, `ts`.

Normalization at the door (`app/routers/webhooks.py`): `canonical_symbol()` uppercases, strips a `EXCHANGE:` prefix and a CME futures month suffix (`_U6`, `_Z6` ...), then applies `SYMBOL_ALIASES` (e.g. XAUUSD→GOLD, XAGUSD→SILVER, USTEC/NAS100→US100, USOIL/WTI/XTIUSD→OIL, BTCUSD/BITCOIN→BTC, ETHUSD/ETHEREUM→ETH, RIPPLE/XRPUSD→XRP, LITECOIN/LTCUSD→LTC, DX1!/USDX→DXY, TNX/UST10Y→US10Y, UST30Y→US30Y (a bond, never the US30 index), VIX1!→VIX, NVDA.NAS-24→NVDA). `normalize_system()` folds "BSv7"→`v7` and anything containing "18"→`v18` (a v7 verdict must therefore send `system:"v7"` and carry Pine's name as `pine_system`). `normalize_tf()` folds `15`→`15m`, `60`→`1h`, `240`→`4h`, `1440`→`1d`; unknown values pass through trimmed. `parse_event_ts()` accepts epoch seconds, epoch milliseconds (>1e12) and ISO-8601. `KNOWN_SIGNAL_STATUSES` is a named vocabulary; an unknown status leaves a `status_unrecognized` event rather than vanishing (v4.18).

Candle ingest (`upsert_candles_report`): unique key `(symbol, tf, ts)`, last-writer-wins, provenance in `candles.source` (`mt5:<login>`), future-dated bars (> now + 3 min) refused, forming bars (`ts + tf` not yet passed) refused, malformed rows refused, and the reply reports `stored / rejected_future / rejected_forming / rejected_malformed` so the reporter can compare SENT to STORED.

## The evidence tables (the MEMORY of the V7 plan)

- `lane_observations` (v4.0, `services/collector.py`): one immutable row per (symbol, engine, closed bar) for all four deterministic lanes — auto-v1 (15m/40 bars, 24h horizon), scalp-v1 (15m/12, 12h), session-v1 (1h/24, 48h), swing-v1 (4h/40, 120h) — WAITs included. Context at birth: structure, ATR, `entry_dist_atr`, `vol_ratio`, bias, news, regime, spread (UNKNOWN unless under 10 min old), macro, snapshot fingerprint, `distance_provenance` (v4.52). Outcomes by `ruleset=lane-resolve-v1`, pinned by test to `ai_analyst._resolve`: fill?, time-to-fill, MAE/MFE in R, final R, TP1/SL/TIMEOUT/NO-FILL/NO_DATA.
- `decision_records` (three-lane rounds: Pine/bot vs auto vs blind AI), `session_candidates` (pre-council funnel, `SC-` ids), `market_snapshots` (v4.2, immutable market states with 24h outcomes), `event_reactions` (v4.24, event × asset macro channels DOLLAR/RATE/DOLLAR+RATE/UNEXPLAINED), `desk_messages` (v4.29, every management judgement journaled `UNVALIDATED`), `outlooks` (v4.39, weekly/monthly theses with scenarios; no confidence column exists and `confidence`/`probability`/`chance` are refused by name), `scan_observations` (scanner outcomes), `ai_calls` (spend ledger), `feed_depth_probes` (v4.43).

## The Trade Desk, lanes and read models

`services/desk.py` (v3.19+) answers "what are the nearest levels for THIS asset now" for every tracked symbol (`tracked_symbols` = `SELECT DISTINCT symbol FROM candles`) in four horizons, composed from one frozen `DecisionSnapshot` (`services/decision_snapshot.py`, one `scanner.build_snapshot` read threaded through session view and plan since v3.2). Every level is a stored structural level or fixed ATR arithmetic; a stale feed produces NO levels. The lanes are PAPER RESEARCH; the validated production plan remains `planner.build_plan` alone (approved signal, 12h lifecycle, scoped to the user's accounts). `/desk` keeps one cheap cached evidence line; the thirteen historical aggregations moved whole to `/evidence` in v5.11 (`evidence_integrity`: contamination report, distance funnel, distance consistency, far-bucket cuts, news cut, MFE/MAE, birth provenance; `desk.distance_confounders`; sensor versions).

Supporting read models (each versioned by name, each FAULT-not-raise): `trend_context` (trend-ctx-v1, EMA200 + MTF, needs 200 closed bars per tf), `outlook.board`/`scorecard` (outlook-score-v1, `COVERAGE_FLOOR = 0.6`), `market_map` (market-map-v1: event playbooks PRE_EVENT → INITIAL_MOVE → WAIT_15M_STRUCTURE → WAIT_RETEST → NORMAL_EVALUATION, cross-asset pressure, MARKET VIEW ≠ TRADE DECISION, why-not-now checklist), `mgmt` (mgmt-v1 management envelope: HOLD/PROTECT/MOVE_SL/TP1/TRAIL/EXIT_WARNING/EXIT/STOP_THROUGH; stop = `V7_FACT`, structure = `DESK_DERIVED`; never-widen SL law), `position_state` (position-state-v1: NONE/BUY_OPEN/SELL_OPEN/HEDGED/MULTI/SIDE_UNKNOWN from broker rows only), `bar_clock` (bar-clock-v1: one bar, open-anchor and close-anchor ages both printed; gate stays on OPEN), `feed_diag` (feed-diag-v1: FEED_WIDE / SYMBOL_ONLY / MARKET_CLOSED / NEVER_POSTED / CANNOT_SEPARATE), `news_lens` (news-lens-v1: `calendar_risk`, `symbol_news`, `event_window`), `fail_soft`, `freshness` (LIVE / STALE / UNKNOWN / INVALID), `reaction`, `brief` (Daily Market Brief; deterministic scenarios, AI narrator optional and fact-checked), `v7_view` (renders v7's artifacts; `setup_edge` is a RENDERER, never a computation), `brain_view` (one page per symbol, guard test forbids new intelligence), `engineering` (seven watchers: candle_freshness, bias_coverage, heartbeats, fallback_id, signal_volume, git_production_match, payload_contract; incidents append-only, INC-nnnn ids never renumbered; APPROVE/REJECT is a notebook, no deploy path).

## Candles, the reporter and the clock

The reporter fetches closed bars only (MT5 `copy_rates_from_pos` from position 1, v1.3.0), converts every bar per-bar through the broker's DST calendar (`BB_BROKER_TZ`, Europe/Athens, v1.5.0), validates the configured timezone against a two-witness offset detection (`detect_broker_offset`: 24/7 markets first, staleness measured between witnesses, ≥2 agreeing fresh symbols incl. one 24/7, else REFUSE), re-verifies every cycle and stops pushing if the answer changes, retries on timeouts and 5xx (v1.6.0), and reports its identity on the VPS heartbeat (v1.7.0). Timeframes come from `BB_CANDLE_TFS` (1m exists for MAE/MFE evidence, pruned after 90 days); symbols from `BB_CANDLE_SYMBOLS`; `python mt5_reporter.py backfill` and `depth` are one-shot commands. Platform-side, `services/candle_audit.py` finds shifted parallel series (off-grid rows, shifted twins, `season_check`, `grid_check` season-aware since v4.47, `depth_status`, `wipe_series` gated on a dump + a fresh depth probe), and `services/market_time.py` owns the canonical `TF_MINUTES`/`TF_SECONDS`, `closed_only()`, `market_status` (weekend-aware, `CRYPTO_247`) and `market_reference_time` (frozen exactly while a market is closed, v4.82).

## The live chart bridge

`services/bridge.py` (v4.21) proxies the bot box's HTTP candle feed (`http://<bot-box>:5001/candles?symbol=&tf=&n=&live=1`) server-side for the HTTPS chart; reads `candles` OR `rows`, `ts` OR `time` (v4.32); translates canonical names to the broker's outbound ticker only (`BROKER_TICKER`, US100→USTEC, v4.98); scrubs the key from error strings; falls back to stored CLOSED candles badged `STORED (delayed)` (v4.28); and never writes to the candle table (guard test). The key provisions itself via `/webhooks/brain/bridge-config` (v4.23).

## Risk, accounts and the SaaS layer

`RiskLimits`, `BotSettings`, `SymbolSetting`, `CopierLink`, emergency-stop flag: user/admin decisions written to `AuditLog` with actor (Iron Rule 3). The sweeper engages the emergency stop on daily-loss or consecutive-loss breaches and notifies on silent bots (docs/DEPLOYMENT.md). Executors are expected to poll `GET /api/v1/stats` for the flag — the platform never pushes. Auth: email-first verification (v1.2.0), optional Twilio SMS OTP, JWT session cookies, TOTP 2FA, trusted devices, open-redirect guard on login (v4.99). Email config lives in `/admin/email` encrypted (v4.93). Billing: plans, subscriptions, wallet ledger, invoices with VAT identity (23% Poland default), coupons, affiliate clicks.
